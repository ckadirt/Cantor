One atomic truth on the node

Finalization now commits four facts together: verified artifact, completed job, song header, and one owner-library change. A crash cannot leave a valid completion permanently missing from the library. 

artifact + completed job + song + library change
                         └─ one SQLite transaction

The old M2 completion is backfilled idempotently. A corrupt completed artifact becomes a visible failure/tombstone instead of a fabricated song.

Sync cannot blank the library

A full sync captures one library revision and walks signed newest-first cursors. Pages remain staged and invisible. Only the final page replaces that node's cache; then incremental sync catches edits made during paging. 

old cache visible → stage page 1…N → atomic replace → changes since N

If a page, parser, app, or connection fails, the old cache survives. If history is too old, full_sync_required safely restarts the same process.

A patch includes expected_revision. If another phone edited first, the node returns the current header; it never silently overwrites it.

Privacy boundary

Principal B tries… Result
List A's library Only B's rows.

Use A's page cursor Invalid cursor; no data.
Wait for A's changes No A header or hint.

The relay stores no library metadata, but it can still read payloads until M6 end-to-end encryption. M3 protects paired users from each other—not yet from the carrier.

What changed on the phone

The library merges known nodes into one timeline. Search covers title, caption, tags, model, and node locally. Views separate favorites, offline headers, and trash. Pull-to-refresh never blanks cached rows.

DETAILS fetches the full private request and provenance only when tapped. Rename, tags, favorite, trash, and restore go back to the owning node. The UI says “remote master” because M3 performs no audio download.
