CANTOR · PRIVATE LIBRARY · MILESTONE 6

The relay routes.
It does not read.

M6 puts one authenticated Noise channel around the existing app protocol. Identity enters only after the node proves its pinned transport key; control and audio then travel as ciphertext.

The whole idea

PinEd25519 signs the node's separate X25519 key.
ProveNoise NK authenticates the node first.
AuthenticateExisting app identity runs inside Noise.
ExchangeJSON and raw audio become opaque binary frames.

What changed

Node keyA random noise.key is stored mode 0600. The familiar Ed25519 node key signs its public half, so the relay cannot substitute one.
Handshake ordersecure.init → offer → Noise step 1 → step 2. Only then may app identity, pair proof, prompts, or library data leave the phone.
RelayIt reads only carrier version, ciphertext length, and the session ID needed for routing. Application kinds and bytes stay encrypted.
AudioThe node encrypts raw 64 KiB artifact chunks. Base64 is recreated only on the phone after decryption for the existing native file API.
Fail closedBad signature, key change, plaintext fallback, tamper, replay, reordering, wrong session, malformed length, or exhausted limits kills the channel.

What the relay still learns

Room identity, IP/network metadata, connection time, direction, frame size, and traffic rhythm remain visible. The relay can also delay, drop, or close traffic. M6 protects payload confidentiality and integrity; it is not anonymity, traffic padding, or endpoint-at-rest encryption.
