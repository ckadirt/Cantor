M5 turns finished node audio into a small, verified phone copy. A download can survive interruption; only the exact complete bytes can play offline.

The mental model

DeriveWAV stays canonical; Opus is replaceable.
ResumePhone opens at its real partial length.
VerifyLength + SHA-256 gate promotion.
Own locallyCache may evict; pin may not.

What changed

Two artifactsmaster.wav is PCM truth. delivery.opus is 48 kHz stereo Ogg Opus at 160 kbit/s.
Safe publishingStatic libopus writes a temp file, fsyncs, verifies, renames, then publishes metadata.
Durable transferOne 64 KiB chunk is outstanding. The phone acks only after native append + fsync.
Hard integrityWrong offset, owner, digest, length, expiry or SHA-256 fails closed. Partials never play.
Offline policyCache is 256 MiB LRU. Pinned audio moves outside cache and cannot be evicted.

Why stop-and-wait?

The plan suggested four chunks in flight. M5 starts with one because every acknowledged byte is then unambiguously durable on disk. It costs round trips, but survives an app kill without pretending buffered bytes are saved.

Deliberately not claimed

This is download-then-play, not streaming. Playback is foreground Android only. M5 traffic is still JSON/base64 visible to the relay; M6 owns end-to-end confidentiality.
