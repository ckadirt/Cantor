M4 makes generation recoverable. A phone can request pause, the node saves an engine checkpoint, and a restarted daemon resumes the same stage only after proving every byte still belongs to the exact job and engine.

The mental model

RunOne engine stage does work.
SaveNode fsyncs an opaque blob.
ConfirmSQLite publishes the new revision.
ResumeExact-compatible engine consumes it.

The node never decodes checkpoint contents. It understands the envelope: identity, stage, provenance, size and digest.

What changed

Stage driverDone advances; Paused re-enters the same stage.
DurabilityBlob + metadata + active pointer are fsynced before a paused update is sent.
CompatibilityRequest hash, model digests, engine family/ABI/build/backend and SHA-256 must all match.
ControlsPause, resume, cancel and retry return the canonical revisioned job—not optimistic UI fiction.
RecoveryPaused stays paused after restart. Interrupted work selects the newest valid source or falls back safely.
RetentionKeep the active source plus one prior boundary; terminal checkpoints expire after 24 hours. Audio is untouched.

Why the native worker is unusual

The shipped ABI-1 engine cannot safely destroy and recreate contexts inside one process.

Real drills produced two reproducible segfaults: freeing between diffusion/decode, and creating a second context after a completed job. Cantor therefore owns one exact-compatible context on one dedicated thread and reuses it across stages and sequential jobs. Durable stage boundaries still exist; a daemon restart creates a fresh context and loads the verified checkpoint.

The app showed “Pausing at a safe point”, then “Paused during diffuse” after restart. Resume completed at revision 47. The node stayed below its 6 GiB cgroup limit. A second-job probe reused the retained context and paused in plan without another backend/model load.

Deliberately not claimed

M4 does not make relay traffic end-to-end encrypted—that remains M6. It also does not physically purge trashed master audio: M5 must first define transfer references and tombstones. The conservative rule today is to refuse new work before deleting canonical user data.
